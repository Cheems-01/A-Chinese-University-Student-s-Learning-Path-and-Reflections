## 2026.11.25 晚

晚上开始搞 STM32 的开发环境，从零开始装。

先是在淘宝上比了几个套件。49.2 那套看着全，但没有仿真器，买回来还得再补；119 多出来的数码管、点阵、步进电机，都是教程后面才用的东西；最后定了 54.4 那套，含 ST-Link。判断方法就一句话：套餐名里有没有仿真器。

Keil 下了很久。开始只有几百 KB/s，换了网才跑到 7 MB/s，900 多 MB 下了几分钟。装到了 D 盘，许可证换成 Community 版，免费，那个 32KB 代码限制也没了。

装器件包的时候 Pack Installer 里一个器件都没有，最后是手动把 pack 解压进去的。

顺手用命令行把整条工具链跑了一遍：armclang 编译、armasm 汇编、armlink 链接、fromelf 转 hex，出来一个点灯的 hex，说明工具链是真的通了，不是看着通。

工程文件第一次被 Keil 打开的时候变成了空壳，分组全没了，后来改用解析器重建，现在五个分组都在。编译 0 错误、22 个警告，警告全是库里 2010 年那批老代码带来的。

CHM 手册乱码，干脆解包成 HTML，自己写了个中文入口页，十个模块一点就进去，比翻 CHM 快多了。

顺便把 ADS 的工程翻了一遍，搞明白两边真正不一样的地方：初始化都是调库函数，无非一个用 zf_driver、一个用标准库；但中断的挂法完全相反。TC264 进中断后硬件自动关了全局中断，要手动开才支持嵌套；STM32 是函数名对上向量表，嵌套默认开着，谁打断谁全看 NVIC 优先级。

现在有一个带标准库的工程了，手册、中断和 DMA 的中文速查都塞进去了，编译能过。

接下来打算自己从头写代码，不抄例程了。
